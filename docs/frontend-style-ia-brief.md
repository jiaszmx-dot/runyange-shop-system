# 润阳阁云店铺前端风格与信息架构简报

## 1. 总体定位

- 气质关键词：
  - 母婴安心感
  - 轻奢高级感
  - 温暖、轻盈、专业
- 明确避免：
  - 医院感
  - 传统 ERP 感
  - 过度花哨
  - 冷冰冰的财务后台感
  - 字太小、步骤太多、按钮难找

## 2. 参考吸收

### 2.1 信息架构参考

- 收银主界面参考：
  - 左侧会员与订单区
  - 中间操作区
  - 右侧项目/商品选择区
- 页面体系参考：
  - 首页
  - 收银页
  - 报表页
  - 会员资料页

### 2.2 视觉风格参考

- 大面积浅底
- 轻柔的薄荷绿 / 奶油白 / 柔粉高光
- 卡片式分区
- 圆角偏大
- 柔和阴影
- 画面通透，不拥挤
- 图表与数据块要“轻”，不要压迫

### 2.3 品牌参考

- 参考 Logo：
  - 儿童形象带来亲和与母婴安心感
  - 深棕 + 暖黄适合作为品牌识别点
- 视觉策略：
  - 主界面不直接做成厚重棕色
  - 用浅奶油底 + 薄荷绿主色
  - 用深棕和暖金做局部品牌强调

## 3. 视觉方向

## 3.1 配色建议

- 主色：
  - 薄荷绿 `#58C8A8`
  - 深薄荷 `#2F9D7E`
- 背景：
  - 奶油白 `#FCFAF7`
  - 暖雾白 `#F6F0E8`
- 辅助：
  - 柔粉 `#F7E7EA`
  - 香槟金 `#D9BC8D`
- 文字：
  - 深可可 `#352A28`
  - 次级棕灰 `#756864`

## 3.2 组件气质

- 卡片：
  - 大圆角
  - 浅描边
  - 非重阴影
- 按钮：
  - 主按钮用薄荷绿
  - 次按钮用浅底描边
  - 重要确认按钮尺寸偏大
- 图表：
  - 不做深色背景图表
  - 用浅底、细线、圆角柱状图、柔和色块
- 表格：
  - 表头轻
  - 行高略大
  - 操作按钮避免过密

## 4. 信息架构

## 4.1 老板/管理员首页

第一屏最重要的 3 个指标：

1. 今日营收
2. 充值金额
3. 到店人数

第二层信息建议：

1. 今日客单数
2. 待回访会员
3. 员工业绩排行
4. 热门项目
5. 库存预警
6. 加盟店经营概况

布局建议：

- 顶部：门店切换、日期、快捷动作
- 第一行：3 个核心经营卡片
- 第二行：趋势图 + 到店/充值趋势
- 第三行：待办与预警
- 第四行：门店/员工/项目排行

## 4.2 收银页

流程固定为：

1. 搜会员
2. 选项目
3. 选员工
4. 选扣费方式
5. 确认优惠
6. 收款
7. 打小票

页面布局建议：

- 左栏：
  - 会员搜索
  - 当前会员信息
  - 已选项目
  - 已选员工
  - 优惠与扣减
  - 应收/实收摘要
- 中栏：
  - 当前步骤操作区
  - 员工选择 / 扣费方式 / 优惠确认面板
- 右栏：
  - 项目/商品大卡片网格
  - 分类切换
  - 搜索

交互原则：

- 平板优先
- 单击区域大
- 当前步骤清晰
- 付款前信息一眼能核对
- 底部保留固定结算区

## 4.3 员工移动端

第一优先：

1. 今日服务人数
2. 个人提成

第二优先：

1. 待跟进会员
2. 回访提醒
3. 推荐充值记录

布局建议：

- 顶部：
  - 今日概览卡
- 中部：
  - 待办任务
  - 今日服务列表
- 底部：
  - 回访入口
  - 推荐记录入口

## 4.4 会员与资料页

- 会员列表页：
  - 搜索
  - 标签筛选
  - 余额 / 次卡 / 赠送次数概览
- 会员详情页：
  - 基础资料
  - 家庭成员
  - 消费记录
  - 充值记录
  - 回访记录
  - 推荐关系

## 4.5 报表页

报表风格基调：

- 浅色底
- 轻卡片
- 先总览后明细
- 尽量避免传统财务软件式密集表格压屏

优先报表：

1. 营收总览
2. 充值分析
3. 到店与订单分析
4. 员工提成分析
5. 项目销售排行
6. 会员增长与复购

## 5. 交互原则

1. 信息轻一点，但关键数字必须醒目。
2. 收银页优先保证“快”和“稳”，再考虑花样。
3. 移动端按钮必须适合平板点按。
4. 多步骤流程不要真的拆成很多页，尽量同屏完成。
5. 危险操作要二次确认，尤其退款和返现。

## 6. 我将据此采用的默认实现假设

1. 主色采用薄荷绿，不采用医院蓝。
2. 大盘首页采用轻仪表板风格，而不是传统 ERP 表格首页。
3. 收银页采用左会员订单、右项目选择的高效率布局。
4. 品牌 Logo 主要用于登录页、导航区和空状态，不会满屏堆砌。

## 7. 这份简报的作用

- 作为后续前端实现的风格基线
- 作为页面原型与组件设计的约束
- 尽量把返工前置到现在，而不是等 CRUD 全写完再返工
